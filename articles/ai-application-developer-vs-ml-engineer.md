# AI Application Developer vs ML Engineer

## Introduction

In today's world, we're being bombarded with AI jargons making us feel overwhelmed about the innovations in AI world.

Everyone is suddenly calling themselves an AI Engineer. But what does that actually mean?

If you're already a software developer, should you become an AI Application Developer or an ML Engineer?

Although the titles sound similar, they involve very different kinds of work.

## Difference

I'm a Full Stack Developer who primarily works with the modern JavaScript ecosystem - React, Next.js, Nest.js for building apps.

We use these libraries and frameworks to create an app that targets a business problem rather than developing our own framework from scratch.

We never think about crete our own front end framework (at least initially). Most application developers rarely need to understand React's internal rendering engine to build production applications. We simply adopt mature frameworks.

In React, we learn concepts like state management, Virtual DOM, create single page application (SPA). We rarely think about how React schedules rendering or reconciles the Virtual DOM.

React core team on the other hand, does the work on renderering engine, fixing bugs in the Hooks implementation, introducing new features/hooks that enchances both user and developer experience.

Now if you see that theres a Front End Developer that uses React to build and then there are React core contributors who aren't into making web apps directly but maintain the library to create web apps

This is the similarity of AI Application Developer and ML Engineer.

## Who is AI Application Developer

LLMs are already trained and ready to use, but you're solving a specific problem which LLMs might not be well trained or missing the required data.
Now with the help of SDKs you can provide context using Prompt Engineering, provide real data to these models with the tool calls and leverage the model's inference capabilities.

This is what an AI application developer is. You just used model's SDK, created a system prompt and tools which are functions that'll retrieve data to the model to generate the output.

From previoust analogy for web development, we don't think about the implementation of let's say `useState` or `useEffect` but we know how we can use them to store state and perform side-effects respectively.

## What about ML Engineer

This is where analogy of React core developer comes into picture.

ML Engineers are the one who do the development (or engineering) of LLMs. And it involves collection of data, Natural Language Processing, creating Neural Networks for next token predictibility, back propagation to improve correctness of tokens, design, fine-tune and deply models. Some specialize in building or adapting large language models, while others work on recommendation systems, computer vision, forecasting, or other ML applications.

## Conclusion

So, as an application developer, it's always good to understand the system at high level. But the effort should be directed towards the development which leverages the capabilities of models for new or enhancing the features improving overall experience of AI.

AI doesn't eliminate software engineering, it changes where developers create value.

If you're already a software engineer, becoming an AI Application Developer is often an extension of your existing skills. Becoming an ML Engineer, on the other hand, requires diving much deeper into machine learning, mathematics, and model development.

Both roles are valuable—they simply solve different problems.
